# v0.1 범위와 완료 기준

2026-10-28 · M0 검토 반영본. 목표는 Android에서 접수한 주문을 통신 단절과 프로세스 종료 후에도 보존하고, POS에서 같은 요청의 효과가 중복되지 않음을 보여주는 것이다.

## 대상 환경과 구현 경계

| 구성 | 결정 |
|---|---|
| 사용자 환경 | Windows PC, 확보 예정인 삼성 Android 기기. 기종·OS는 아직 확인 전 |
| 앱 | Kotlin, Compose, Flow, Room. 프로세스 단위 전송 Controller와 저장 가능한 화면 초안을 분리. 화면은 연결 설정·주문·진단의 최소 구성 |
| SDK | Android와 분리한 Kotlin 핵심 정책 + TCP·Room 어댑터. 배포용 SDK 패키징은 후속 |
| POS | Python 표준 라이브러리 TCP 서버와 SQLite. 별도 웹 대시보드는 제외 |
| 통신 | 숫자 IPv4와 포트 직접 입력, TCP 한 방식, 단말 1대·POS DB 1개 |
| 실행 수명 | 앱이 전경에 있을 때 전송. 백그라운드 전환 시 네트워크 작업을 멈추고 요청을 보존 |
| 버전 | JDK 17, Gradle 8.11.1, AGP 8.9.2, Kotlin 2.1.20, compile/target SDK 35. minSdk 23 잠정값이며 실기기 확인 전 지원 검증으로 주장하지 않음 |

## 필수 기능

1. 주문 본문·요청 ID·로컬 접수 순서를 원자적으로 저장한다. 성공한 commit 이후에만 `기기에 접수됨`을 표시하고 전송한다.
2. POS commit의 응답을 로컬 DB에도 commit한 뒤 `POS 저장 확인`을 표시한다.
3. 단절이나 응답 제한 시간 초과 시 기존 ID로 재시도한다. 자동 시도 상한 이후에는 요청을 남기고 전송을 일시 중지한다.
4. POS는 같은 ID·같은 내용에 기존 결과를 반환한다. 같은 ID·다른 내용은 명시적으로 거부한다.
5. 앱 프로세스 종료 후 명시적으로 재실행하면 미확인 주문을 복원한다.
6. 장애 주입과 실제 저장 결과를 확인할 수 있는 로그·조회 수단을 제공한다.
7. 핵심 자동 테스트, 의도적 결함 2개의 검출 기록, CI의 배포 후보 생성 조건을 제공한다.
8. 주문 없는 연결 확인과 POS DB 식별로 같은 POS의 IP 변경을 지원한다. 확인 필요 주문은 보존하면서 다음 PENDING을 처리하고, 사용자 중지는 재실행에도 유지한다.

## 첫 공개 시 필요한 증거

- 정상 왕복과 S01 단절, S02 응답 유실, S03 프로세스 종료 시연.
- 동일 요청 ID·본문을 기준으로 송신 DB, POS DB, UI의 최종 상태를 대조한 결과.
- 요청 ID 재발급 및 ACK 전 완료 처리 결함을 기존 테스트가 검출한 기록.
- 검증 커밋, 명령, OS·기기, 실행 결과, 미실행 범위를 담은 보고서와 2~3분 영상.
- 명세·핵심 JVM·Windows/Linux POS·Android 정상/장애 검사 성공 후에만 CI의 시연 후보 묶음 생성 작업이 실행됨. 검증된 debug APK를 재사용하고 source/APK 해시와 검증 범위를 기록한다.
- Android 실기기를 확인하지 못했으면 에뮬레이터 검증이라고 명시. 실기기 검증 완료로 표시하지 않음.

## 후속 범위

NSD 자동 검색, BLE·USB, 다중 단말, Toxiproxy, 여러 Android 버전의 자동 실행, DB 마이그레이션·롤백, 주문 취소·환불, 장기 부하 검증, 백그라운드 지속 전송, 인증·TLS를 후속 목록으로 둔다. v0.1은 합성 주문만 사용하는 통제된 LAN 데모이며 실결제·실매장 배포를 지원하지 않는다.

새 기능은 세 시연을 완성하는 데 필요한지 먼저 판단한다. 필요하지 않으면 공개 준비 이후로 배치한다. 2~3주는 목표 범위이며 주당 투입 시간과 기기 준비가 확인되지 않은 납기 약속이 아니다.
