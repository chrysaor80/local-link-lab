# Local Link Lab 진행 관리

갱신: 2026-10-28 Asia/Seoul. 사용자 환경은 Windows, 삼성 구형폰 확보 예정. 기종·Android 버전·주당 투입 시간은 미확인이다.

## 진행 상태

| 단계 | 산출물 | 현재 상태 | 종료 기준 |
|---|---|---|---|
| M0 | 범위·프로토콜·시나리오·판단 기록·검토 요청 | 명세 검사 통과, OPUS 검토 대기 | 명세 자체 검사, OPUS의 범위·계약 검토 반영 |
| M1 | Android → POS 실제 왕복 | 예정 | 실제 앱과 Room, 실제 TCP와 POS DB, UI 결과 대조 |
| M2 | 장애 3종과 핵심 검증, 결함 사본 2종 | 예정 | 시나리오별 근거 확보, OPUS 검토 반영 |
| M3 | CI·APK·영상·공개 설명 | 예정 | 실행 증거와 한계가 일치하는 지원용 산출물 |

## 담당과 변경 관리

- Codex: 범위·일정·실행 근거 관리, 조사·구현·테스트·수정.
- OPUS: 고정 커밋의 설계와 구현을 독립 검토. M0 검토 요청을 작성했으며 이번 검토본에 대한 의견은 아직 받지 않음.
- 사용자: 실제 폰 연결·설치·기기에서만 가능한 관측, 설계 설명 연습.
- 검토 의견에는 번호, 우선순위, 근거, 재현, 채택/보류/기각 이유를 남긴다. 중요한 계약 변경은 DECISIONS와 명세에 함께 반영한다.

## 다음 작업

1. M0를 하나의 커밋으로 고정하고 OPUS에게 SCOPE → PROTOCOL → SCENARIOS → DECISIONS 순으로 전달한다.
2. M1에서 최소 Android 빌드를 먼저 실행해 도구 버전·SDK·저장 권한·LAN 접속을 확인한다.
3. Android 기기 확보 시 Windows에서 모델·API 레벨을 기록한다. 확보 전에는 에뮬레이터 사용 여부를 명시한다.
4. 실제 주문 한 건 왕복 후 M1 검토 요청을 묶는다. 계약을 바꿀 필요가 있으면 근거와 영향 시나리오를 함께 적는다.

## 미해결 사항

- 원격 독립 저장소: 사용자가 `chrysaor80/local-link-lab` 공개 저장소를 생성했다. GitHub 연결 도구로 명세와 스크립트를 올린다. CLI의 GitHub API 접근은 사용할 수 없으므로 연결 도구를 사용한다.
- Android 빌드 환경: 현재 실행 환경에서 Java runtime은 확인했지만 JDK compiler·Android SDK·adb는 아직 준비하지 않음. 앱 빌드·기기 테스트를 완료했다고 표시하지 않는다.
- OPUS 직접 실행 연결은 없음. 검토자는 저장소/커밋 또는 전달 묶음을 읽고 결과를 이 채팅에 전달한다.

## 이번 작업의 실행 증거

`python scripts/check_spec.py` 성공: 메시지 예제 12개, 시나리오 정의 10개, 결함 사본 계획 2개, 내부 문서 링크 10개. 공개 문서에서 알려진 비공개 저장소 이름·링크와 회사 제품명을 점검했다. 소스와 무관한 제품 테스트는 실행하지 않았다.

검토자는 전달된 원격 커밋을 기준으로 읽는다. 오프라인 전달 묶음의 `REVISION.txt`에는 그 묶음의 기준 커밋을 기록한다. 이 검사는 메시지 구조와 문서 참조의 일관성에 한정된다. APK 빌드, TCP 왕복, Android 종료 복원, 결함 검출은 모두 NOT_RUN이다.

`spec.yml`은 명세 검사만 실행하는 CI 설정이다. GitHub Actions의 실제 실행 여부는 해당 커밋의 Actions 결과를 확인한다. v0.1 제품 테스트·APK 생성 조건은 M3에서 구현한다.
