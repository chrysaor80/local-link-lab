# 2~3분 시연 영상 촬영 계획

상태: 촬영 계획 준비. 실제 촬영·편집·영상 게시 완료로 표시하지 않는다. 고정 소스 SHA와 촬영 환경을 첫 화면에 표시한다. 실기기 미확보 시 Android API 29 에뮬레이터로 촬영하고 그렇게 표기한다.

| 시간 | 보여줄 장면 | 설명과 확인점 |
|---|---|---|
| 0:00–0:15 | 앱·POS·검증 결과의 전체 구성 | “연결이 끊기거나 앱이 종료돼도 접수한 주문을 보관하고 같은 ID로 복구합니다.” 실결제 승인 기능은 포함하지 않음 |
| 0:15–0:35 | 정상 주문 접수 → 기기 보관 → POS 저장 확인 | 접수 전 ID와 POS 1개 행/영수증 대조. 화면 완료만으로 성공을 판단하지 않음 |
| 0:35–1:00 | POS 중지 → 새 주문 접수 → 같은 DB 재시작 | PENDING을 보존하고 같은 ID로 복구. 시도 한도를 넘긴 경우 수동 재개임을 숨기지 않음 |
| 1:00–1:35 | POS commit 사건 → 첫 ACK 유실 → 재시도 | 이미 POS에 있는 주문을 다시 받아도 행 1개·최초 영수증이 유지됨. 가장 중요한 시연 |
| 1:35–2:05 | 보관 주문 → 앱 PID 종료 → 명시적 재실행 | PID가 바뀌고 주문/사용자 중지 복원. 자동 앱 재실행이라고 설명하지 않음 |
| 2:05–2:35 | 정상 6개 PASS와 결함 사본 3개 검출 | ID 재발급은 추가 POS 행, ACK 전 완료는 POS 없는 완료 상태로 검출. 사용자 중지 무시도 검출. 환경 오류와 구분 |
| 2:35–2:50 | 보장 범위와 다음 과제 | 에뮬레이터/LAN 구분, 실제 저메모리·전원 차단·실결제는 미검증. 추가 통신 방식은 후속 |

## 촬영 경로

- 정상·서버 중지 복구: [Windows·Android 안내](DEMO_QUICKSTART.md)를 따른다. 실제 PC/폰에서 성공한 경우에만 LAN 시연으로 표시한다.
- ACK 유실과 commit 직후 종료: 사건 기반 `lab.android_run`을 **일회용 에뮬레이터**에서 사용한다. 수동으로 서버를 잠깐 끄는 것을 ACK 유실 시연이라고 부르지 않는다.
- 자동 실행기는 앱 데이터를 초기화하므로 폰에서는 실행하지 않는다. 에뮬레이터 serial을 확인하고 각 촬영에 새 출력 폴더를 쓴다. 기존 결과 폴더는 덮어쓰지 않는다.

깨끗한 checkout에서 `python -m lab.package_candidate stamp`로 빌드·stamp를 완료하고 해당 debug APK를 설치한 에뮬레이터의 예시다. 자동 실행기의 S01은 차단 뒤 항상 수동 재개하며, 자동 재시도 장면은 S02로 촬영한다. 첫 터미널에서 녹화를 시작하고, 두 번째에서 ACK 유실 시나리오를 실행한다.

```text
adb -s emulator-5554 shell screenrecord --time-limit 45 /sdcard/local-link-s02.mp4
```

```text
python -m lab.android_run --serial emulator-5554 --scenario S02 --out artifacts/video-s02-take1
```

녹화가 종료된 뒤:

```text
adb -s emulator-5554 pull /sdcard/local-link-s02.mp4 artifacts/video-s02-take1/screen.mp4
```

최초 영상 캡처 명령은 아직 실행하지 않았다. 실제 촬영에서는 영상·같은 take의 result.json·POS DB·기준값을 함께 보관한다. CI 로그를 화면에 보여주면 “저장된 CI 실행 기록”으로 표시한다. 서로 다른 실행의 ID/영수증을 이어 붙여 하나의 왕복처럼 편집하지 않는다.

개인 알림·계정·폰 serial이 화면에 나오지 않게 확인한다. 재시도 대기 구간을 줄이는 편집은 경과 시간을 표시하고, 실패한 take도 원본 근거로 보존한다.
