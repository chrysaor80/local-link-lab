# M2 승인과 후속 P3 처리

[OPUS 원본 보고](OPUS_M2_RECHECK_REPORT.md)의 판정은 **M2 수정본 6c7187d 승인, 기존 필수 조건 M2-01 해소**다. M3 후보 조건 70a6347도 요구를 충족하며 새 발견 세 건은 P3, 시연을 막지 않는다고 판정했다. 원본 [재현 패치](m2-recheck-tests.patch)를 변경 없이 보존했다. 아래 후속 보강은 구현 담당이 M3에서 수행하며, 이 새 코드까지 OPUS가 재검토했다고 표현하지 않는다.

| 발견 | 처리 | 재현·변경 |
|---|---|---|
| R-01 | 채택 | 원본 패치의 대조군 PASS/누락 사건 재현 FAIL을 일반·-O 모두 확인했다. 후보가 S03의 서로 다른 PID, 종료 방법, 종료→재실행→복원 관측 순서와 snapshot PID를 요구한다. S01 차단/재개, S02 commit/ACK 유실/응답, C07 다른 DB 확인/원복 사건도 검사한다. |
| R-02 | 채택 | 소스를 되돌려 clean HEAD가 된 상태에서도 git-ignored APK가 바뀌면 기존 검사 두 개가 통과함을 회귀 테스트로 재현했다. 로컬 실행도 stamp의 소스·APK·실행 종류를 요구한다. 공개 stamp 명령은 Gradle을 먼저 실행해 성공한 빌드만 기록한다. 결함 stamp는 원본 SHA·변이 diff 해시·APK 해시를 묶고 정상 APK 복원도 실제 설치 해시를 기록한다. |
| R-03 | 채택 | 전송 로직과 관측 순서는 유지한다. S01은 차단→수동 재개→동일 ID 1건이며 recovered_by_resume=true다. S02는 추가 재개 없이 ACK 유실 후 자동 재시도하므로 false다. 문서의 두 경로를 구분했다. |

OPUS 재현 테스트는 정상 fixture에 PID 사건을 추가하면서, 실패 사례가 그 사건을 명시적으로 제거하도록 조정했다. 원본의 발견 의도를 유지하고 잘못된 PID·역전된 사건/시각·다른 DB에 전송한 기록도 거부하도록 확장했다. 판정기와 입력 자료가 일치한다는 것만으로 실제 기기 검증을 대신하지 않는다.

로컬 Python 전체 49개와 후보/재확인/빌드 신원 검사 23개(-O) PASS. 과거 70a6347의 원본 사건·관측 6개도 새 사건 순서 검사와 일치했다. 과거 기록에 새 stamp 검사를 실행했다고 소급하지 않는다. 새 소스의 Android 에뮬레이터·결함 빌드·정상 복원·후보 생성은 CI에서 재실행하고 실제 checkout SHA와 원본 artifact를 별도 증거에 기록한다.

사용자의 삼성 폰은 충전 중이며 기종/API를 아직 모른다. 폰 준비와 독립적으로 API 29 에뮬레이터에서 실제 Android 앱/Room/TCP와 POS를 실행하고 화면을 캡처한다. 삼성 폰·Windows LAN은 별도 후속 검증이다. M2의 승인된 검토 단계는 닫고 이후에는 실기기·시연 준비를 진행한다.
